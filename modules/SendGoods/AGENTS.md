# SendGoods 项目说明

## 沟通与判断

- 回答问题时避免过分夸赞，优先保证准确性。
- 不默认认定用户或 Codex 的判断一定正确；遇到不确定字段、页面变化、表格结构变化时，应主动说明依据和不确定点。
- 输出尽量结构化，先给结论，再给关键依据和下一步建议。
- 涉及页面读取、表格写入、图片下载时，必须区分“已验证”和“推断”。

## 项目目标

本项目用于从 Temu Agent Seller 页面采集待发货/备货相关信息，并按拿货表模板生成或填写 Excel。

项目形态优先定位为 PyQt 桌面软件，不默认做 Flask Web 项目。Playwright/Chrome 只负责页面读取和数据采集。

Git 仓库地址：

- `https://github.com/lXFCL/SendGoods.git`

目标页面：

- `https://agentseller.temu.com/stock/fully-mgt/order-manage-urgency`

核心采集字段：

- 备货单号，例如 `WB2606104882401`
- 备货母单号，例如 `WP2606108703980`
- 商品货号，例如 `SZW-2138`
- SKU 货号，例如 `SZW-2138-M`
- 颜色，例如 `黑色`、`白色`
- 尺码，例如 `S`、`M`、`L`、`XL`、`XXL`
- 备货件数
- 商品正面高清图片

## 技术方向与运行环境

- 用户希望优先使用 `PutawayAIRobot` 这个 conda 环境。
- 如果后续确认使用名为 `flask` 的 conda 环境，应理解为“环境名叫 flask”，不代表项目必须使用 Flask 框架。
- 当前机器如果找不到 `PutawayAIRobot` 环境，不要直接假定环境名；先提示用户确认是否应使用已有的 `flask` 环境，或需要补建/导入 `PutawayAIRobot`。
- 桌面界面优先使用 PyQt。
- 不要因为环境名叫 `flask` 就把项目实现成 Flask Web 服务。
- 页面读取优先使用 Playwright，读取已登录 Chrome 状态时可使用 Chrome 插件/扩展方式。
- 不要在未确认的情况下把账号、Cookie、LocalStorage、密码等敏感信息写入文件或日志。

## 打包规则

- 软件需要打包成 Windows 单个 exe。
- 打包产物应包含运行所需的 Python 环境依赖，包括 PyQt、Playwright、openpyxl、Pillow、requests 等。
- Playwright 的浏览器二进制需谨慎处理：程序优先连接本机 Chrome 调试端口；如要在无 Chrome/无 Playwright 浏览器的电脑离线运行，需要另行验证浏览器二进制是否已随包带齐。
- 打包使用 `flask` conda 环境时，应理解为使用该环境中的依赖，不代表项目使用 Flask 框架。
- 当前打包入口：
  - `build_exe.ps1`
  - `SendGoods.spec`
- 目标产物：
  - `dist/SendGoods.exe`
- 需要打包的资源：
  - 程序源码依赖
  - `1.cleaned.xlsx` 模板
  - Playwright Python 运行所需资源
- 不要打包多余运行时文件：
  - `.browser-profile/`
  - `downloads/`
  - `outputs/`
  - `__pycache__/`
  - `build/`
  - 历史测试输出文件
- exe 运行后产生的 Excel、图片缓存、浏览器资料目录应保存在 exe 所在目录旁边，不应写回 PyInstaller 临时目录。

## Temu 页面读取规则

- 优先读取页面 DOM/接口中的真实文本，不要只依赖截图 OCR。
- 表格可能存在虚拟滚动或懒加载；只读取当前 DOM 通常不能代表全部数据。
- 如需完整读取，应滚动表格并去重累计，或分析页面请求接口。
- 每条 SKU 明细至少应解析出：
  - 商品货号：从商品信息中的 `货号：SZW-xxxx` 提取。
  - SKU 货号：从 SKU 信息中的 `SKU 货号：SZW-xxxx-尺码` 提取。
  - 颜色和尺码：从 `属性：黑色-M`、`属性：白色-XL` 等字段拆分。
  - 备货件数：读取 `备货件数` 列。
- 同一备货单下可能存在多个 SKU 行；后续 SKU 行可能不重复显示商品图片和商品货号，应沿用该备货单/商品组的上一条商品信息。
- 读取动作应保持只读，不点击会提交、创建、修改、加入发货台、打印、上传或下载的按钮，除非用户明确要求。

## 图片规则

- 不使用表格缩略图作为最终图片。
- Temu 表格图片常见缩略图格式示例：
  - `https://img.kwcdn.com/product/open/...-goods.jpeg?imageMogr2/thumbnail/180x`
- 点击图片放大后，实际高清图通常是去掉 `?imageMogr2/thumbnail/180x` 以及后续查询参数后的地址。
- 已验证示例：
  - 缩略图：`https://img.kwcdn.com/product/open/d1d7cde1b07e4f07b4a7105ff55ced06-goods.jpeg?imageMogr2/thumbnail/180x`
  - 高清图：`https://img.kwcdn.com/product/open/d1d7cde1b07e4f07b4a7105ff55ced06-goods.jpeg`
- 实现时应优先点击预览确认高清图地址；若页面结构稳定，可将去查询参数作为兜底规则。
- Excel 中“图案正面”需要放完整清晰图片，不要放 180x 缩略图。

## Excel 模板规则

当前模板文件：

- `1.cleaned.xlsx`

当前已确认结构：

- 工作表：`Sheet1`
- 左侧黑色区域：`A:J`
- 右侧白色区域：`L:U`
- 第 3 行为颜色标题：
  - `A3:J3` 为黑色
  - `L3:U3` 为白色
- 第 4 行为字段标题。
- 黑色区域列：
  - `A` 序号
  - `B` 货号
  - `C` S
  - `D` M
  - `E` L
  - `F` XL
  - `G` XXL
  - `H` 合计件，已有公式 `=SUM(C行:G行)`
  - `I` 图案正面
  - `J` 图案反面
- 白色区域列：
  - `L` 序号
  - `M` 货号
  - `N` S
  - `O` M
  - `P` L
  - `Q` XL
  - `R` XXL
  - `S` 合计件，已有公式 `=SUM(N行:R行)`
  - `T` 图案正面
  - `U` 图案反面
- 数据从第 5 行开始。
- 行高约为 `99.95`，图片插入时应适配单元格大小，保持可辨识。
- 合计列已有公式，写入尺码件数时不要覆盖合计公式。

## 填表规则

- 商品货号使用不带尺码的部分，例如 `SZW-2138`。
- SKU 货号 `SZW-2138-M` 应解析为：
  - 商品货号：`SZW-2138`
  - 尺码：`M`
- 颜色为黑色时写入左侧黑色区域。
- 颜色为白色时写入右侧白色区域。
- 同一颜色、同一商品货号可能有多个尺码，应合并到同一行的不同尺码列。
- 同一颜色、同一商品货号、同一尺码出现多次时，件数应累加，除非用户另有要求。
- 每个商品货号的正面图只需放一张清晰完整图片。
- 若存在无法识别颜色或尺码的数据，不要静默丢弃；应输出异常清单供用户确认。

## 建议实现模块

- `main.py`：PyQt 桌面软件入口。
- `ui/`：PyQt 界面代码，负责按钮、进度、日志、文件选择和结果展示。
- `temu_reader.py`：负责读取 Temu 页面、滚动表格、提取订单/SKU/图片数据。
- `excel_writer.py`：负责按 `1.cleaned.xlsx` 模板写入货号、尺码件数和图片。
- `image_utils.py`：负责高清图片地址转换、下载、尺寸处理。
- `models.py`：定义采集结果的数据结构。
- `outputs/`：保存生成后的 Excel。
- `downloads/images/`：保存临时下载的高清图片。

## 验证要求

- 写入 Excel 后，应重新读取生成文件，确认：
  - 黑色数据只写入左侧区域。
  - 白色数据只写入右侧区域。
  - 尺码列对应正确。
  - 件数没有漏加或错列。
  - 合计公式仍存在。
  - 图片已插入到“图案正面”列，且不是 180x 缩略图。
- 对采集到的总 SKU 行数、成功写入行数、异常行数给出摘要。

## 安全边界

- 默认只读取页面和生成本地 Excel。
- 不自动提交 Temu 页面中的任何操作。
- 不保存账号密码、Cookie、Token 或浏览器会话文件。
- 如后续需要调用 Temu 接口，应只保存必要的非敏感业务数据。
